# F1 Racecraft — F1 赛事复盘 Demo

[打开在线演示](https://owenmao-builder.github.io/f1-racecraft/) · [策略实验室](https://owenmao-builder.github.io/f1-racecraft/?race=netherlands#strategy)

一个面向 F1 粉丝与新观众的非官方交互演示。无需登录，直接打开即可体验。

## 体验范围

面向普通观众和 F1 粉丝的交互原型。左侧固定导航，右侧最新已完赛大奖赛的大图入口；通过“精彩赛点 → 为什么 → 另一种选择 → 三维观察”的路径降低理解门槛。

当前样本覆盖截至 2026 年 9 月 19 日最近十场已完赛大奖赛：西班牙、意大利、荷兰、匈牙利、比利时、英国、奥地利、巴塞罗那-加泰罗尼亚、摩纳哥、加拿大。默认最近一场西班牙站；列表为固定资料样本，不会自动刷新下一站赛事。

- 比赛选择：按时间倒序排列的十场比赛，支持横向浏览、一键返回最近一场、通过网址保留所选比赛。
- 全场概览：每场独立的真实赛事海报、精选看点、完赛摘要与官方来源；西班牙站有三个深度赛点，其他九场各有一个精选赛点。
- 赛点分析：官方精选与来源解读，可跳到策略实验室继续自定义推演。
- 自定义条件推演：调整成功率、成功收益、失败损失、缠斗损失、跟车成本、风险和比较圈数，比较立即进攻与先跟住的期望时间代价。
- 车手数据：西班牙站提供 22 位车手分类与合成曲线示例；其他场次展示已核实的前三名与官方完整赛报入口。
- 策略实验室：目录下分为「策略观察室」和「策略研究院」。观察室用分步讲解说明换胎时间账、进站窗口和决策判断；研究院选择赛点、修改假设、比较换胎与攻防方案。两边可带着同一车手和圈次切换，精选 VSC 实验收进研究院的折叠区。
- 三维慢镜头：真实 GLB 双车网格，侧前方 / 纯侧面 / 侧后方，0.25× / 0.5× / 1×、播放暂停、拖动进度和阶段跳转。
- 我的赛点：当前浏览器本地收藏。

结果、事件叙事、赛事照片基于 FIA、Formula1.com 和 McLaren 的公开资料，链接在网站“数据与来源”中。

## PRD 可直接验证的问题

1. 用户能否在首页 10 秒内发现“这场比赛哪里精彩”？
2. 每个赛点的事实、解释、假设区分是否清楚？
3. 更改条件后，用户能否理解结论为什么变化？
4. 侧面三维是否帮助理解并排与前出，而非只增加视觉噱头？
5. 新手解释是否能降低术语门槛，同时不过度打断老车迷？

下一步应独立定义：真实历史赛事接入、遥测时间轴同步、轮胎与能量数据可用性、轨迹校准与误差标记、事故热点统计口径、可执行策略约束及回测。

## 本地运行

这是无构建步骤的静态网站。从项目目录运行 `python3 -m http.server 8881 --directory dist`，访问 `http://127.0.0.1:8881/`。

`dist/races.js` 保存十场资料和海报映射，`sources/` 保存图片出处；`dist/app.js` 管理页面和交互；`dist/scene.js` 管理三维场景；`dist/styles.css` 定义响应式主题。字体、图标和 Three.js 使用版本固定的外部 CDN，三维模型与主图保存在本项目内。收藏不上传服务器。

## 自定义分析的数据与开源复用

`dist/analysis.js` 提供工作台，`dist/analysis-engine.js` 处理证据时间边界和教学公式，`dist/data/*.json` 保存十场公开历史快照。`scripts/cache-openf1.py` 为公开数据获取脚本，会跳过已有快照并对限流进行有限重试。自定义分析的圈速为真实历史记录，与车手数据页的合成遥测示例分开。

- 已使用 [OpenF1](https://github.com/br-g/openf1) 的参赛名单、圈速、轮胎段、间隔、位置及赛会消息。每个快照保存查询 URL、获取日期和 session key。
- 证据锚定所选车手的圈起点。目标弯号仅标记待研究位置，尚未标定弯角轨迹，不能据此解释该弯的制动点、走线或真实意图。
- 胎龄为轮胎段开始时已跑圈数加当前圈号减轮胎段起始圈，不代表实测磨损或温度。
- 双车间隔采用锚点之前八秒内、相互不超过三秒的领跑者差值样本；套圈字符串不会转换成秒数。数值为采样估计，不是精确空间距离。
- 圈速只使用锚点之前已完成的至多三个有效圈，排除进出站圈，不校正燃油、交通和旗况。两车样本圈号可能不同，图中分别标注。
- 赛会消息仅显示锚点之前两分钟内的记录；没有消息不代表全场绿旗。1.5 秒为研究提示阈值，不是规则门槛或经过拟合的缠斗判定器。
- [FastF1](https://github.com/theOehrly/Fast-F1) 可支持后续遥测、距离对齐和弯角标定；本版尚未集成。
- [TUM race-simulation](https://github.com/TUMFTM/race-simulation) 可参考整场仿真、进站和轮胎选择；不能直接还原弯角走线与车手意图。“进站与轮胎推演”从 TUM 基础模型扩展为非线性条件模型，详见文末；“现在争，还是先跟住”继续使用自有教学公式。
- [AI Race Engineer](https://github.com/Sissighn/ai-race-engineer) 的弯角时间损失和双车比较可供后续评估，本版未集成。

本次验证：十场共 660 个早段、中段和末段请求通过决策时间边界检查；相同车手、缺失圈次拒绝；降低假设成功率可反转比较顺序。浏览器已检查跨比赛查询、精选与自定义切换、假设滑块，以及新增 WebMCP 工具的合法与非法调用。

## 不可比较与部分数据的处理

- 分别显示每位车手的轮胎和有效圈速；一方缺记录不会隐藏另一方的事实。
- 车距不可比较时，区分无同时圈次、近期采样不足、采样未对齐、套圈标记和参照缺失。
- session_result 补充赛后 DNF/DNS 分类，仅用于解释数据覆盖，不当作决策时刻已知信息，不据此认定精确退赛时间。
- 有数据缺口时，可选系统按有效间隔排序的其他对手；仅提示数据可比较，不声称正在缠斗。
- 荷兰站 RUS/VER 第 32 圈回归：保留 RUS 硬胎 14 圈、此前三个有效圈均值 76.63 秒；VER 无同时有效圈次，单独显示赛后退赛分类与缺口原因。RUS/PIA 一键切换可恢复双车对比。

## 初版 TUM 线性策略推演（历史实现，当前模型见文末）

- 带入所选车手的当前干胎配方、胎龄与计划剩余圈数；只读取当前圈及之前的轮胎段。对手缺数据不阻断可用的单车模型；未知胎龄、雨胎、最后一圈显示相应边界。
- 比较不再进站、本圈结束进站、等待若干圈、最佳一停、最佳两停。第一套新胎由用户选择；两停的第二套在三种干胎中搜索。最优仅指所列候选范围。
- 进站窗口曲线、胎段时间轴、轮胎收益/进站损失/升温损失拆解联动更新。配方性能、升温和进站损失均为假设，可编辑；默认值源于上游 YasMarina 2017 示例，未对本场拟合。
- `dist/tum-strategy-engine.js` 为 TUM 基础模型绿旗线性子集的独立 JavaScript 移植，按 LGPL-3.0 提供可读可替换源码，保留原计算源码、许可证及修改说明。不是完整 Python 引擎或 VSE 的托管服务。
- 省略各方案共同的基础圈速、燃油和起始项，只输出相对时间差；不会输出绝对完赛时间、位置预测、真实意图或弯道最优解。
- `scripts/generate-tum-fixtures.py` 从未修改的 TUM 原始 Python 生成独立结果；`node scripts/validate-tum.mjs` 已通过 90 组数值一致性检查、76 组历史起点，以及未来数据和末圈边界检查。

本轮浏览器验证：等待圈数、进站损失、衰减调整、方案点击、跨比赛重置与末圈提示；390 px 与 320 px iframe 中实测页面无横向溢出，手机时间轴与成本拆解可读。

- 赛点分析页提供「在策略实验室自定义推演」入口；VSC 赛点继续打开其对应教学案例。
- 本轮浏览器检查：旧链接重定向、侧栏与面包屑、模式切换保留参数、原教学案例调参/重置、赛点分析返回实验室。

本轮追加验证：跨比赛工作台重新带入胎龄和剩余圈数；无重复 DOM id；320 px 下实验室模式选择与表单无页面横向溢出。

## 换胎策略互动解说（初版验证记录）

策略实验室的「进站与轮胎」新增“策略师带你看”，用时间投资解释换胎：旧胎的代价 → 进站先付款 → 新胎逐圈追 → 终点算总账。默认解说当前假设下的最佳一停，也可切换不再进站、立即进站、等待和两停，与下方方案选择同步。

- 约 15 秒的逐圈播放、暂停、章节跳转和圈次拖动；切换实验室模式、页面隐藏、重新查询时停止播放。
- `dist/pit-ledger.js` 将已有 TUM 方案拆成每圈账目，进站圈末扣除进站成本，下一圈计升温；曲线正数表示相对不再进站的时间收益，与下方“时间代价”图的方向在各自标题中说明。
- 回本只计算最后一次进站后、能保持到终点的非负余额。不会把起点的零、短暂穿越零线或下一次进站前的回本误当成最终回本。
- 解说跟随轮胎性能、进站损失、等待圈数与方案改变。亏损、打平、未满足配方约束都有对应说明，不将假设结果描述为真实车队判断。
- 当前荷兰站 RUS L32 示例：L46 换中性胎，轮胎收益 23.53 s，进站 21.50 s，升温 1.00 s；L71 起持续回本，净省 1.03 s。该优势未包含交通或对手反应，默认参数未拟合赛事。

验证：`node scripts/validate-pit-story.mjs` 对照 90 组原始 Python 独立结果核对逐圈账本合计，覆盖费用发生时刻、两停、无进站、到终点不回本与暂时回本后再次亏损。原 TUM 检查继续通过。浏览器检查逐段解说、播放、拖动、切换模式暂停、参数翻转、无效值恢复、跨赛事及最后一圈边界；320 px 与 390 px 实测页面和解说卡片无横向溢出。


## 当前换胎模型：非线性逐圈成本

修正动机：初版将 TUM YasMarina 2017 的示例参数直接映射成现代软、中、硬胎；硬胎只有 0.02 s/圈龄的线性衰减，长胎段没有后期加速，无法代表当前比赛的配方行为。不是所有线性模型都不合理，而是未标定的弱衰减默认值使这个演示偏向长时间不换胎。

当前 `dist/race-strategy-engine.js` 为独立 LGPL-3.0 扩展。原线性模块、来源和 Python 对照测试保留。

每圈轮胎代价：`D_c(a) = δ_c + k1_c × a + k2_c × a² + q_c × max(0, a − A_c)²`。

剩余方案成本：`T = Σ_i (B_i + D_c(a_i) + W_i + Q_i) + Σ_j P_j`。

净时间收益：`G = T_no_more_stops − T_plan`，正数表示省时。所有方案从同一决策起点算到同一终点；共同的基础圈速、燃油质量变化与赛道演化 B 抵消。进站后的起圈胎龄归零，再继续老化。已有胎龄、配方与剩余赛程来自历史快照，其余均是可编辑假设。

| 中等耗胎工程情景 | 新胎差值 δ（s） | k1（s/圈龄） | k2（s/圈龄²） | 拐点 A（圈龄） | q（s/圈龄²） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 软 | 0 | 0.055 | 0.0012 | 22 | 0.012 |
| 中 | 0.35 | 0.035 | 0.00065 | 30 | 0.010 |
| 硬 | 0.70 | 0.022 | 0.00035 | 40 | 0.008 |

**这些是工程情景，不是 Pirelli 2026 实测系数，也不是按当前比赛拟合的预测。** 低耗胎把衰减项乘 0.35、拐点乘 1.25；高耗胎分别乘 1.8、0.85。拐点不是安全寿命或爆胎阈值，长胎段外推尤其不可靠。将 k2 和 q 清零可还原线性模型。后续正式产品需要使用长距离跑数据，在燃油、旗况、交通、温度校正后拟合，并做留出赛事验证。

- 自动搜索未来零、一、两停，下一套可自动比较三种干胎或手动固定；两停第二套始终比较三种。没有额外“进站奖励”，也不保证换胎一定划算。
- 加入假设新胎库存，默认各两套；不是实际剩余胎组。检查已知历史配方与两配方假设，不声称覆盖全部赛事规则。
- 绿旗损失默认 21.5 s；VSC/SC 的本圈窗口默认 13/11 s，全部可改且不是本赛道实测。低损失仅作用于当前圈末进站，后续恢复绿旗，不把中和成本无限推广，也不仿真压缩车阵。
- 每次升温与额外交通成本在出站后第一圈合并记账；交通是额外耗时参数，没有模拟具体赛车和位置。
- 优先显示与其他可行方案中最快者的时间差；不再进站若违反配方假设，或其完赛胎龄超过假设拐点15圈，显著提示这只是长胎段的理论外推（15圈为提示阈值，不是物理寿命）。
- 同一方案在衰减项 ±25% 下重算，显示敏感性范围；不是概率、置信区间或重新优化后的范围。
- 当前荷兰 RUS L32 / H14 / 剩余41圈，中等耗胎自动模式：L50 换软胎，轮胎收益 42.77605 s，进站21.5 s，升温1 s，净省20.27605 s，L63起持续回本。若固定下一套为中性胎，最佳一停净省约19.68 s。均为条件示例，不是实际车队最佳策略。

公开依据：[TUM 轮胎模型源码](https://github.com/TUMFTM/race-simulation/blob/96ef2c2021982217be008fe458df47c1a72da071/helper_funcs/src/calc_tire_degradation.py)支持二次衰减；[Pirelli 2026 轮胎选择](https://press.pirelli.com/tyre-compounds-selected-for-zandvoort-monza-and-madrid/)说明赛道负荷、温度和维修区损失影响一停/两停选择。来源支持建模因素，不提供本项目默认系数。

验证：`node scripts/validate-race-strategy.mjs` 通过120组独立逐圈参考计算、18个历史起点、穷举最优核对、零/一/两停结果、胎组限制、本圈中和窗口、交通成本、敏感性与非法参数检查。原线性模型与逐圈账本的90组 Python 对照仍通过。浏览器验证了耗胎/成本翻转、指定配方、VSC窗口、无效输入恢复及交通扣账。

追加浏览器检查：320/390 px 无横向溢出；轮胎库存清零会排除换胎候选；编辑系数后标为自定义；比赛前段高耗胎两停比可行一停快约14.72 s，强制不换胎的巨大理论差值有醒目提示和不同解说。

`.github/workflows/pages.yml` 将 `dist/` 发布到 GitHub Pages。推送到 `main` 会自动更新网站，也可在 Actions 中手动运行 Deploy GitHub Pages。

应用使用相对资源路径，可从 `/f1-racecraft/` 子路径运行；历史数据随站点提供，体验 Demo 不需要 API 密钥或后台服务。

本地测试：`node scripts/validate-race-strategy.mjs`、`node scripts/validate-tum.mjs`、`node scripts/validate-pit-story.mjs`。若要重新生成 TUM 对照样本，先下载上游 race-simulation 项目及其依赖，再运行 `python3 scripts/generate-tum-fixtures.py /path/to/race-simulation`。

## 策略实验室的两个子栏目

- `#strategy-observe`：策略观察室。专业策略师视角的知识课堂，一次显示一个主题；换胎讲解沿用现有成本模型，隐藏调参面板，参数与实测信息明确区分。
- `#strategy-research`：策略研究院。自己选择车手与圈次、修改条件、比较方案；证据与解读按需展开。原有换胎计算、攻防假设与 VSC 教学实验保留。
- `#strategy` 默认进入观察室，`#custom` 进入研究院，旧 `?lab=cases#strategy` 进入研究院的精选实验。观察室与研究院传递已分析的比赛、车手、对手、圈次和弯号；不把教学例子的模拟结果标成车队实际决策。
